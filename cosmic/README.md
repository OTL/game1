# コズミック・イーター

小さな岩のかけらから始まり、あらゆる天体を喰らって成長し、最終的に**ブラックホール**になったらクリアの、
2D 宇宙成長（育成×サバイバー）ゲームです。

## 遊び方

- **移動**：マウスドラッグ（またはタッチ）でプレイヤー天体を動かします。画面中央から指・カーソルを離した方向へ慣性を伴って進みます。
- **捕食**：自分より小さい天体にぶつかると、相手を破壊して質量（経験値）を吸収できます。破片は自動でこちらに引き寄せられます。
- **被弾**：自分より大きな天体にぶつかるとダメージを受けます。HP が 0 になると、直前の進化段階の始まりまで戻ってやり直しになります（強化はその段階の開始時点まで巻き戻ります）。
- **レベルアップ**：質量が一定量に達するたびに、3 枚のカードから強化を 1 つ選べます。
- **進化**：質量のしきい値に到達すると次の姿へ進化します。

  岩石片 → 小惑星 → 準惑星 → 惑星 → 巨大ガス惑星 → 褐色矮星 → 恒星 → 巨星 → 中性子星 → **ブラックホール（クリア）**

- **捕獲（惑星以上で解放）**：進化段階が「惑星」以上になると、自分よりずっと小さい敵（質量が自分の
  35%以下）をロックオンして捕獲し、周回する衛星にできます。PC は **Q キー**、スマホは画面右下の
  🛰ボタンで捕獲します。同時に保有できる数は進化段階に応じて増加します（惑星/巨大ガス惑星:1 →
  褐色矮星:2 → 恒星:3 → 巨星:4 → 中性子星:5 → ブラックホール:6）。捕獲した衛星は自機を公転しながら
  触れた敵にダメージを与え、近くの破片（小天体）を自動で引き寄せて質量獲得を手伝いますが、
  自分よりずっと強い敵に触れられ続けると破壊されてしまうこともあります。保有数は左上のHUD
  （🛰 x/y）に表示されます。既存の「衛星」アップグレードは汎用の小型衛星として引き続き機能し、
  捕獲システムとは独立に共存します（どちらも同じ公転・接触ダメージの仕組みを共有）。
- **ゲームモード**：タイトル画面で選べます。
  - **通常モード**：クリアまで約 60 分を狙ったペース配分（序盤の進化は数分、終盤の進化は 8〜10 分程度）。
  - **加速モード（お試し）**：短時間（5〜6 分程度）で最後まで試したいプレイヤー向けの、これまでの
    速いペースをそのまま残したモード。
  
  モードはセーブデータに保存され、「つづきから」では選んだモードのまま再開されます。
- **セーブ**：数秒ごと・進化やレベルアップなどの節目に自動で保存されます（ブラウザの localStorage）。タイトル画面の「つづきから」で再開できます。
  ※本アップデートでバランス・セーブ形式を変更したため（`cosmic-eater-save-v3`）、以前のセーブデータは
  引き継がれず「はじめから」扱いになります。

## 強化（アップグレード）の例

溶岩惑星・惑星環・希少鉱脈・重力場強化・硬質地殻・衛星・磁場収束・オーロラ帯・推進機関・地殻再生・
核融合暴走（クリティカル）・密度増加・彗星の尾・隕石シールド・加速衝突・質量転換効率・重力感知・磁気嵐など、
20 種類以上。恒星以降でのみ解放される「太陽フレア」「コロナ質量放出」「重力波」「伴星」「不死の芯」といった
上位の強化もあります。同じ強化を重ねて選ぶとレベルが上がり効果が強化されます。

## 実機フィードバック対応（終盤の破綻・画質・ペーシング）

実機（スマートフォン）でのプレイフィードバックにより、終盤（恒星 Lv13、プレイ時間 03:53）で
画面全体が巨大でボケた敵テクスチャに埋め尽くされ、MISS・ダメージ数値がスパムし、廃止したはずの
点線軌道円も残っているという破綻状態が報告された。原因分析と対応は以下の通り。

### 1. 終盤の「敵が画面を埋め尽くす」問題の原因
「分裂」ではなく **敵同士の合体（`updateEnemyMutualGravityAndCollisions`）の無制限な連鎖** が
主因だった。敵同士が近づくと大きい方が小さい方を吸収して質量が増えるが、この吸収質量に上限が
無かったため、プレイが長引くほど1体がどんどん肥大化し、`massToRadius`（質量の立方根）で半径も
際限なく育っていた。加えて敵のスポーン数上限（旧: 26体）や画面内密度の制御が緩く、遠くのスポーン
も含めて狭い範囲に敵が密集しやすかった。対応:
- 敵1体の質量に `BALANCE.enemyMassCapMult`（プレイヤー質量の4倍）の上限を導入。合体・スポーンの
  どちらでもこれを超えない。上限に達した合体は超過分を破片として放出する（吸収側の得は残す）。
- ワールド全体の敵・破片の総数に上限（`maxEnemies`=20, `maxFragments`=40, `maxTotalBodies`=55）を
  設け、超過分はプレイヤーから最も遠いものから間引く（`pruneBodyCounts`）。
- プレイヤー近傍の敵密度にも上限（`nearViewSoftCap`）を設け、密集している間は新規スポーンを控える。
- 質量比の大きい「脅威」個体は、外周寄りの遠い位置にのみスポーンするようにし、プレイヤーより
  大幅に大きい敵がいきなり近接して視界を覆うことを防いだ（質量上限と合わせて、脅威敵の見た目
  サイズはプレイヤーの 4^(1/3)≒1.6 倍までに収まる）。
- 破片（吸収可能な質量粒）はそもそも敵化しない設計のままであることを確認・維持（分裂の連鎖が
  発生しない）。

### 2. 巨大な敵がモザイク状にボケる問題の原因
固定の低解像度テクスチャキャッシュ（近似描画: 最大64px角、フル品質: 最大220px角、球面テクスチャの
元絵も200×100px固定）を、画面上の実表示サイズまで拡大描画していたことが原因。加えて
devicePixelRatio（Retina等で最大2倍）が解像度計算に反映されていなかった。対応（LOD: Level of Detail）:
- `Renderer.drawRotatingGlobe` で、天体の画面上の実表示ピクセル数（半径×2×devicePixelRatio）に
  応じてキャッシュするテクスチャの解像度を動的に決定するように変更（近似描画の上限を160px角、
  フル品質の上限を480px角に拡大）。
- 球面投影の元になる正距円筒図法テクスチャ（equirectangular）の解像度も、必要な表示サイズに応じて
  4段階（140×70 〜 680×340）で再生成するようにし、大きく見える天体ほどクレーターなどのディテールが
  つぶれず見えるようにした。
- `ctx.imageSmoothingEnabled`/`imageSmoothingQuality` を明示的に高品質設定にした。
- `node cosmic/tools/simulate-pacing.js` とは別に、Playwright で実際に終盤相当の巨大天体を画面いっぱいに
  表示して確認済み（後述の検証結果を参照）。

### 3. 点線軌道円の完全削除
`Renderer.drawLockonMarker`（ロックオン対象の周りに薄くパルスする点線の輪を描く関数）自体を
削除し、呼び出し箇所も削除した。ロックオン情報は左上のHUDパネル（`#lockon`）のみで表示する。
ワールド空間に円やガイド線を描く処理はコード上どこにも存在しないことを確認済み。

### 4. MISS・ダメージ数値のスパム対策
被弾・ダメージ処理は毎フレーム正しく計算しつつ、**表示だけ** を対象ごと（敵の uid・プレイヤーの
被ダメージ・プレイヤーの質量獲得）に集計し、`BALANCE.floatFlushInterval`（0.35秒）ごとに合算して
1回だけ浮遊テキストを出すように変更（`queueFloat`/`flushFloatAggregates`）。シールドのMISS表示も
`BALANCE.missFlushInterval`（0.5秒）のクールダウンを設け、接触し続けても毎フレーム表示されないようにした。

### 5. 彗星の尾アップグレードの視覚的な軌跡
移動軌跡に接触ダメージ判定を持つアップグレードは「彗星の尾」（`tail`、`pulseDamage` を
`playerRadius*1.5` の範囲で自機位置に適用）と特定した。これまで対応する見た目が存在しなかったため、
自機の直近の移動履歴（`player.tailTrail`）をフェードする発光プラズマの帯として描画する
`Renderer.drawTail` を追加。帯の太さはダメージ判定半径（`playerRadius*1.5`）と連動させ、見た目と
判定範囲が一致するようにした。

### 6. ペーシング調整（通常モード ≈60分 / 加速モード）
`cosmic/tools/simulate-pacing.js`（Node.js 上で質量獲得を確率的に近似シミュレーションするツール）を
新規作成し、実機フィードバックの実測値「03:53で恒星(Lv13)到達」から接触試行レートを逆算した上で、
進化段階ごとの質量獲得倍率（`NORMAL_STAGE_PACING_MULT`）を調整した。結果:

```
$ node cosmic/tools/simulate-pacing.js
=== 加速モード（お試し）(massGainMultiplier=1.0 固定) ===
  平均クリア時間: 5.3 分   （恒星到達: 3.93分 ≈ 実測の 03:53 と整合）
=== 通常モード（段階別倍率） ===
  平均クリア時間: 59.9 分
    小惑星: 2.78分  準惑星: 6.28分  惑星: 10.81分  巨大ガス惑星: 16.55分
    褐色矮星: 23.05分  恒星: 30.92分  巨星: 40.65分  中性子星: 50.64分
    ブラックホール: 59.92分
```
序盤（岩石片〜準惑星）は数分間隔、終盤（巨星以降）は8〜10分間隔になっており、要求どおりの
ペース配分になっている。この段階別倍率は `creditMass`（質量獲得を行う唯一の関数）内で
一律に適用されるため、キル・破片吸収・パッシブ回収などすべての質量獲得源に一貫して効く。
加えて、ブラウザ内での実機相当の動作確認として、`window` に一時的なデバッグフック
（時間加速・内部state参照・任意ステージへのジャンプ）を追加した実機検証も行った上で、
コミット前にそれらのデバッグコードは削除している。

## 見た目・演出（リアルな宇宙表現）

### 1. 単一光源の一貫したライティング
ワールド全体で共有する「遠方の恒星」を1つだけ定義しており（`WORLD_LIGHT`、超低速にしか角度が
変化しない実質固定方向）、プレイヤーを含む全天体・全パーティクルが常にこの同じ方向から照らされます。
球体（準惑星以上）はテクスチャ側でこの方向のライティング・縁の減光（limb darkening）を焼き込み、
自転しても明暗境界（ターミネーター）は常にワールド座標で同じ向きを保ちます。小さい／不規則な天体は
「形状（アルベド、方向性の光は焼かない）」と「固定シェーディングマスク」を分離して合成することで、
タンブリングしていても同じ光源方向を維持しています。夜側は完全な黒ではなく、背景光でわずかに
見える程度の明るさ（ambient floor）を残しています。彗星の尾・浮遊する塵・破片のハイライトも
すべて同じ `WORLD_LIGHT` を参照するため、画面内のどの天体も矛盾のない「同じ太陽の下」に見えます。

### 2. 小さい天体は球にしない
岩石片〜小惑星クラス（小惑星・彗星核・敵対天体、およびプレイヤーの序盤2段階「岩石片」「小惑星」）は、
円形テクスチャを不規則な輪郭（複数の調和振動を重ねた半径関数）でクリップした「ジャガイモ型」で
描画し、非等速の角速度ゆらぎ（タンブリング）で回転させています。準惑星以上（自己重力で丸くなった
天体：準惑星・惑星・ガス惑星・褐色矮星・恒星・巨星・中性子星・ブラックホール）だけが球体＋自転に
なり、プレイヤーも準惑星へ進化した瞬間にジャガイモ型から球体へ切り替わります。

### 3. ケプラー運動の徹底（静止天体ゼロ）
真空中なので敵天体・破片の速度に減衰摩擦は入れていません。小惑星帯は各々ばらばらな初速のまま
漂流し続け、彗星は視界を高速で横切ります。プレイヤーの質量に応じた簡易重力（`applyPlayerGravity`）
が近傍の天体に働き、質量が大きいほど通過する小天体の軌道が目に見えて曲がります（スイングバイ的
挙動）。敵天体同士も近傍限定の簡易相互重力で緩やかに引き合い（`updateEnemyMutualGravityAndCollisions`）、
接近しすぎると衝突して大きい方が小さい方を飲み込み、破片を放出します。天体数の上限が決まっている
ため、これらはすべて O(n²) の総当たりで計算しても 60fps を維持できます。

### 4. 衝突の運動量保存
敵を撃破したときや敵同士が衝突したときに生成される破片は、親天体の速度をそのまま引き継いだ上に
爆発による放射状の速度を加えます（運動量保存）。破片は個々に回転しながら、以後は減速せず真空を
漂います。

### 5. 彗星の尾は反太陽方向
彗星の尾は進行方向の逆ではなく、恒星（`WORLD_LIGHT`）の反対方向へ伸びます。まっすぐ青い
イオンの尾と、進行方向側へやや曲がる白いダストの尾の2本を描画しています。

### 6. 画のトーン・雰囲気
- 背景に天の川のような微光の帯を1本、ごく薄い視差でドリフト表示しています。
- 漂う微細な塵パーティクルを3層のパララックスで常時流しており、各粒はゆっくり自転していて
  `WORLD_LIGHT` との内積で明るさが変わります（光を受けて煌めくように見えます）。
- プレイヤー（カメラ）が速く動いているときは、進行方向と逆に塵がわずかに尾を引き、スピード感を
  演出します。
- ブルーム風のグローは恒星・巨星・褐色矮星・中性子星・ブラックホールの降着円盤など発光体のみに
  限定しています。
- 薄いビネットは毎フレームの canvas 再描画コストを避けるため、常時表示の CSS オーバーレイ
  （`#vignette`）として重ねています。
- ロックオン対象の表示はワールド空間の円やガイド線を一切描かず、左上のHUDパネル（`#lockon`）
  のみで行っています（実機フィードバックにより、パルスする破線の輪も含めて完全に廃止しました）。

### 天体の球体描画（準惑星以上）
横方向にシームレスな正距円筒図法（equirectangular）テクスチャをオフスクリーンで生成し、縦スライス
ごとに球面へ投影して描画しています。端に近づくほどテクスチャが圧縮される球面マッピング、
`WORLD_LIGHT` 方向のシェーディング、縁の減光、惑星以降は薄い大気の縁光も再現しています。
ガス惑星・褐色矮星・巨星は縞模様が、恒星・中性子星は表面の輝きが自転とともにゆっくり流れて見えます。
パフォーマンスのため、画面上である程度大きく見える天体のみこのフル品質描画を行い、それ以外の
小さい・不規則な天体（ジャガイモ型）は自転位相を離散化した「フレーム」単位で（形状＋固定シェーディング
マスクを合成した）描画結果をキャッシュし、drawImage 1回で済ませることで、多数の天体が同時に映っても
描画コストを抑えています。

### 多層パララックス背景
星空を3層（うち2層は星の瞬き付き）でパララックス表示し、カメラの移動に応じて視差スクロールします。
星雲は星空とは別レイヤーとしてオフスクリーン生成し、ごくゆっくりドリフトしながら明滅（アルファ
ゆらぎ）します。ときおり流れ星も出現します。進化段階が進むにつれ、背景の色調も序盤の暗青から
恒星帯の暖色、終盤の深い紫へと連続的に変化します（彩度は抑えめ、暗部を締めたトーン）。

## 実機フィードバック対応（第2回：終盤の敵サイズ・アップグレードの整合性・実プレイ調整）

### 1. 敵サイズ分布の再設計（根本原因の修正）

**症状**: 前回対応（`enemyMassCapMult=4`）後も終盤で敵が自分より常に大きく、画面を圧迫する。

**根本原因の特定**: 敵の表示半径が `massToRadius(mass) = 6 * mass^(1/3)`（質量の単純な立方根）で
計算されていたのに対し、プレイヤー自身の表示半径は `STAGES` の `radiusBase` テーブルを使った
別の補間式（`playerRadius()`）で計算されていた。序盤の小さい質量では両者はほぼ一致して見えるが、
終盤の質量（数百万〜一千万超）では `massToRadius` が実質破綻し、同じ質量でも敵の方がプレイヤーより
何倍も大きく描画されてしまっていた（例: 質量1300万の場合、`massToRadius` ではワールド半径1400を
超えるが、プレイヤー側の `radiusBase` は最大でも80程度に収まるよう意図的に設計されている）。
これが「敵は常に自分よりデカく見える」体感の直接の原因だった。

**対応**:
- 敵の表示半径を新設の `enemyVisualRadius(mass)`（`entities.js`）に置き換えた。中身は
  `playerRadius()` と全く同じ「`STAGES.radiusBase` を使ったステージ内補間」で、同じ質量なら
  プレイヤーと敵が同じ見た目の大きさになることを保証する。
- 敵1体の**質量**（戦闘力）の上限を `enemyMassCapMult` で `4倍 → 2倍` に引き下げた。
- サイズ**分布**を目標分布（大半は自分より小さい餌、2割前後が同格〜やや大きい、明確に大きい
  脅威は同時1〜2体まで）に基づいて再設計した（`BALANCE.prey/even/threatMassMultRange` と
  `preyChance`/`evenChance`、`data.js`）。
  - 餌（質量倍率 0.15〜0.65）: 76%
  - 拮抗（同格〜やや大きい、0.7〜1.3）: 19%
  - 脅威（明確に大きい、1.4〜2.0）: 5%
- 敵のスポーン基準質量は、実際のプレイヤー質量ではなく `state.enemyScaleMass`
  （log空間で平滑化した緩やかな追従値）を基準にロールするようにし、敵スケールが
  プレイヤー質量に「遅れて追いつく」ようにした。死亡・リスポーン時は即座にリセットする。
- プレイヤー近傍に同時に存在できる「脅威」（質量比 `BALANCE.threatRatioThreshold`=1.3 以上）の
  数を `BALANCE.maxThreatsNear`（2体）で制限し、上限に達している間の新規スポーンは強制的に
  非脅威にロールし直す。
- 画面短辺の40%を超える表示半径にはしない安全弁（`screenRadiusCapFor()`）を、スポーン時・
  敵同士の合体成長後の両方に適用した。質量（戦闘力）と表示半径を分離してクランプすることで、
  「戦闘バランス」と「見た目の上限」を独立に安全に制御できるようにした。
- 敵同士の**合体の頻度**も抑えた。合体した個体には `mergeCooldown`（4.5秒）を設け、
  クールダウン中は合体させず反発（めり込み解消）だけ行うことで、同じ個体が連鎖的に
  肥大化し続けることを防いだ。

**実測結果**（Playwright + Chromiumで自動プレイし、進化段階ごとに集計。詳細は本セクション末尾）:
通常モード・加速モードの両方で、プレイヤー近傍の敵の質量比分布はおおむね目標どおり
（餌74〜100%・拮抗0〜15%・脅威0〜15%、同時脅威数は最大2〜3体）に収まり、近傍の敵の画面占有率は
全ステージを通して最大でも約20%（40%の安全弁は未到達）に収まることを確認した。

### 2. アップグレード説明文と実挙動の突き合わせ

`data.js` の全アップグレードについて、説明文が指すメカニクスが実装と一致しているか1件ずつ
確認した。特に「高速移動」関連の疑いから着手したが、調査の結果、**最も重大な不整合は
「核融合暴走」（会心）と「重力感知」の2つ**だった。

| ID | 名称 | 問題 | 対応 |
|---|---|---|---|
| `critical` | 核融合暴走 | 説明文は「%の確率でダメージが2.2倍」だが、実装は確率要素が一切なく、常に `1 + val%*1.2` を掛けるだけの別物の効果だった（2.2倍という数値もコード上どこにも存在しなかった）。 | 説明文どおりの確率発動クリティカル（`rng()`で判定、成功時ダメージ×2.2）に実装し直した。発動時は「会心!」の浮遊テキストを表示し体感できるようにした。 |
| `sense` | 重力感知 | 説明文は「索敵と警戒の範囲が拡大する」だが、実装は敵AIの索敵範囲に `* 0` を掛けており、**効果が完全に無効化されていた**（プレースボ状態）。 | ロックオンパネルの有効距離（`senseRangeFor()`）をこのアップグレードで拡大するようにし、加えて画面外にいる強大な敵（脅威）を画面端の矢印と距離表示で警戒表示する新機能（`drawThreatWarning`）を実装した。敵AI自体の索敵範囲（プレイヤーを追う/逃げる判定）は変更せず、あくまでプレイヤー側の「察知・警戒」情報として実装した。 |
| `ramspeed` | 加速衝突 | 「高速移動中は〜」という表現だが、実際は現在の移動速度比（0〜1）に連続的に比例するだけで、明確な「高速移動状態」を示す見た目のフィードバックが無く体感しづらかった（ユーザー指摘のとおり）。 | 移動速度が最大速度の60%を超えると自機後方に加速光（グロー）が灯る視覚効果を追加し、説明文を「移動速度が最大速度に近いほど〜。自機に加速光が灯る」に更新して実挙動と一致させた。 |
| `lava` | 溶岩惑星 | 説明文は「与えたダメージの%を質量変換」だが、実装は即吸収（オーバーキル）時のみに限定された特殊処理だった。 | `damageEnemy()` 内に一般化し、接触・波動・衛星などあらゆるダメージ源で一律に効くようにした（説明文どおり）。 |
| `gwave` | 重力波 | 説明文は「周囲の敵と破片を引き寄せる」だが、実装は破片の吸引範囲拡大のみで、敵への重力には一切効いていなかった。 | プレイヤー重力（`applyPlayerGravity`）にも `gwave` のボーナスを適用し、敵にも実際に効くようにした。 |
| `flare` | 太陽フレア | 説明文は「扇状の炎」だが、実装は全方位に均等にダメージが飛ぶ `pulseDamage`（円形）だった。 | 進行方向を中心とした扇形の `coneDamage`（半角約60°）に変更し、視覚的なパーティクルも追加した。 |
| `binary` | 伴星 | 説明文は「ダメージと引力」だが、引力の実装が存在しなかった。 | 伴星の周囲に弱い敵を引き寄せる引力を追加した。 |
| `rings` | 惑星環 | 説明文「環の破片が触れた敵に追加ダメージ」は、実際には環専用の当たり判定ではなく通常の接触ダメージへの一律ボーナスだったため、表現をやや誇張気味だった。 | 実挙動に合わせ「衝撃を増幅し、接触時の与ダメージ+%」という説明文に修正した。 |

残りのアップグレード（惑星環の基礎効果・希少鉱脈・重力場強化・硬質地殻・衛星・磁場収束・
オーロラ帯・推進機関・地殻再生・密度増加・彗星の尾・隕石シールド・質量転換効率・磁気嵐・
コロナ質量放出・不死の芯）は、説明文と実装を突き合わせた結果、既に一致していることを確認した
（変更なし）。

### 3. 実プレイでの調整ループ（Playwright + Chromium）

`/opt/pw-browsers/chromium` を使い、実際に序盤→中盤→終盤→クリアまで自動プレイして計測した。
ヘッドレス環境では `requestAnimationFrame` が著しくスロットルされ実時間で計測すると非効率
だったため、開発時のみ一時的なデバッグフック（rAFに依存せずゲームロジックを同期的に多数
フレーム進める `forceTicks`、進化段階ごとの敵数・質量比分布・画面占有率を集計する `getStats`）を
`game.js` に追加して計測に使用し、**調整完了後にコミット前へ完全に削除した**（現在のコードには
含まれていない）。

調整ループは以下の3周を実施：

1. **1周目**: サイズ分布・質量上限（4→2倍）・合体クールダウンを実装して計測 → 敵の質量比分布は
   改善したが、終盤（巨大ガス惑星以降）で敵の質量比が0に近づき、脅威が全く出現しなくなる
   問題を発見（`enemyScaleMass` を生の質量のままEMA平滑化していたため、指数的に成長する
   終盤の質量に対して追従が全く追いつかなくなっていた）。
2. **2周目**: `enemyScaleMass` の平滑化を対数（log）空間に変更（質量の成長率が一定なら
   比率が収束する性質を利用）。さらに、敵の表示半径が `massToRadius`（質量の単純な立方根）
   のままだったため終盤の質量域で異常値になっていた根本原因を発見し、
   `enemyVisualRadius`（プレイヤーと同じSTAGESベースの補間）に置き換え。画面占有率は
   大幅に改善したが、計測（バッチ末尾の1点サンプリング）では依然「脅威0%」と出ており、
   一瞬だけ出現する脅威をサンプリングが取りこぼしている疑いがあった。
3. **3周目**: 計測ロジックをバッチ内の全ティックを走査する方式に変更し、脅威の遠方スポーン
   バイアス（`farBias`）を調整（0.78→0.68）。再計測の結果、目標分布どおり
   （餌74〜100%・拮抗0〜15%・脅威0〜15%、同時脅威数は最大2〜3体）に収まっていることを確認し、
   最終値として確定した。
